## 1. 适用范围

本篇规定 Huffman 压缩内核与 AES 加密内核的行为、边界与失败模式，覆盖 `CompressionModules/Huffman/` 与 `EncryptionModules/Aes/`。块结构、分割标准与归档整体布局由 ArchiveFormat 根定义，本篇不重复。

## 2. Huffman 内核

### 2.1 块粒度与码长表

内核以 8 MiB 为块粒度（`Constants::BUFFER_SIZE`，`CompressorFileSystem/Commons/include/FileLibrary.h:99`），每块的频次统计、建树与码表互不继承。每块自带一份 258 字节码长表，写在压缩数据之前，解压端只凭该表重建码字，不重建树。

码长表由 `codeTableToPlatUchar` 生成、`spawnCodeTable` 校验：

| 偏移 | 字节 | 内容 |
|---|---|---|
| 0 | 1 | 标记 `'L'` |
| 1 | 1 | `maxCodeLen`，合法范围 1..64 |
| 2 | 256 | 每符号码长，0 表示该符号本块未出现 |

### 2.2 压缩四步

1. `statisticFreq` 累计 256 项符号频次，`finishFreqStat` 把暂存表搬入总表。
2. `genHufftree` 按符号值升序把频次非零的符号压入最小堆，反复合并两个最小频次节点，直到堆只剩一个根。
3. `saveCodeInTab` 由树导出每符号码长，`buildCanonical` 按 (码长, 符号值) 升序重排码字。
4. `encode` 逐字节查表打包，末尾回填填充位数。

上述四步的顺序由 `HuffmanCompression::compress` 固定，码长表在编码前由 `codeTableToPlatUchar` 序列化（`CompressionModules/Huffman/Core/include/HuffmanCompression.h:21-29`）。canonical 规则 `firstCode[L+1] = (firstCode[L] + count[L]) << 1` 使解压端仅凭码长表复现同一套码字。

### 2.3 位打包与结束判据

- 位序为高位先出：码字自 MSB 向 LSB 填入输出字节。
- 每块压缩数据的首字节是填充位数，取值 0..7，等于末字节的补零位数；末字节有效位靠左。
- 解压端校验首字节不超过 7，有效比特总数为 `(块长 - 1) × 8 - 填充位数`，消费到该数即结束，输出达到 `originalSize` 也结束。
- 解码先用 12 bit 主表直查，码长大于 12 的符号走 canonical 逐位回退。

### 2.4 边界四条

| 边界 | 行为 |
|---|---|
| 空块 | 不进入内核：读阶段 `gcount() == 0` 即判文件结束，零字节文件不产出数据块；对空块调用 `compress` 无可定义结果，`genHufftree` 在空堆上取根（`CompressionModules/Huffman/Core/src/Huffman.cpp:68-77`） |
| 全零块 | 256 项频次中只有符号 0 非零，按单符号块处理 |
| 单符号块 | 树根即叶子，该符号独占码字 `0`、码长 1（`CompressionModules/Huffman/Core/src/Huffman.cpp:89-98`） |
| 最大码长 | 硬上限 64，超出抛 `runtime_error`；`spawnCodeTable` 拒收声明值 0 或大于 64 的表（`CompressionModules/Huffman/Core/src/Huffman.cpp:153-156,453-456`） |

失败模式：metadata 长度不等于 258、首字节非 `'L'`、声明码长与重算值不符、编码遇到码长为 0 的符号，均抛 `runtime_error`（`CompressionModules/Huffman/Core/src/Huffman.cpp:269,449,467`）。解码块为空或首字节大于 7 同样抛错（`CompressionModules/Huffman/Core/src/Huffman.cpp:303-313`）。

### 2.5 压缩率上限

码长只由块内符号频次决定，重复串与上下文不参与建模，压缩率下界即块内零阶熵。实测 13.47 GiB / 45,390 文件的数据集上最好约 60%（`README.md:66,90`）。258 字节码长表对 8 MiB 块的开销为 258 / 8,388,608 ≈ 0.0031%，按 `Constants::BUFFER_SIZE` 计算的估值。

### 2.6 吞吐

硬件为 AMD Ryzen 7 8845H，构建口径 `-O3 -DNDEBUG` 并开 LTO（`Y_MultipleAgentWorkflow/Engineering/工程实践.md:82-83`）。

单核内核吞吐，条件为单线程、每 8 MiB 一块、重复取最快一次：

| 阶段 | 吞吐 |
|---|---|
| 编码 | 471.1 MiB/s |
| 解码 | 236.8 MiB/s |
| AES 加密 | 1261.5 MiB/s |
| AES 解密 | 1279.6 MiB/s |

端到端吞吐走完整读-算-写流水线，工人数取默认硬件并行度（`Y_Manager/CompressionLoop.cpp:30-31`），含磁盘 I/O；输入 13.47 GiB / 45,390 文件，压缩 254.3 MiB/s、解压 325.1 MiB/s（`README.md:66-73`）。

AES 吞吐约为 Huffman 编码的 2.7 倍，编解码是主要成本（`Y_MultipleAgentWorkflow/Engineering/工程实践.md:108-110`）。

## 3. AES 内核

### 3.1 密钥派生与口令

主密钥是 SHA-256(口令) 的前 16 字节，输入按 `strlen` 取长，任意长度口令压成 128 位（`EncryptionModules/Aes/src/AesFunctions.cpp:85-91`）。

空串走同一路径，得到固定密钥，等价于公开密钥；界面在加密模式下拒绝空口令提交（`SFC_GUI/src/MainWindow_Compression.cpp:449-451`）。

### 3.2 IV 与 CTR

每次 `encrypt` 用 `BCryptGenRandom` 生成 16 字节随机 IV 并前置在密文之前，解密从输入前 16 字节取 IV（`EncryptionModules/Aes/src/mainCircle.cpp:24-36,47`）。采用 CTR 的理由是无需填充：每次 `encrypt` 的输出恒为明文长度加 16 字节 IV，一个源块经元数据块与数据块两次加密，共多 32 字节；目录块的 IV 占用分割标准预留的 16 字节槽，归档不增长（`CompressorFileSystem/Commons/include/FileLibrary.h:123-126`）。

链模式固定为 ECB（`EncryptionModules/Aes/src/AesFunctions.cpp:107-114`）；源码注释记载本机不支持原生 CTR，故以 ECB 批量加密 128 位大端计数器块生成密钥流（`EncryptionModules/Aes/include/My_Aes.h:27-28`）。在支持 AES-NI 的 CPU 上由 CNG 走硬件路径。

### 3.3 加密范围

- 每个数据块：码长表加密一次，压缩数据加密一次，各自携带 16 字节 IV（`Y_Manager/CompressionLoop.cpp:242-243`）。
- 目录块：收尾阶段由 `CatalogFinalizer::finalize` 整体加密并原地回写，IV 占块前 16 字节，`BlockSpan::ivSlotPos()` 返回 `startPos - Constants::IV_BYTES`，即 `startPos - 16`（`CompressorFileSystem/Commons/include/FileLibrary.h:148,181`；回写路径 `CompressorFileSystem/ArchiveFormat/src/CatalogFinalizer.cpp:59-66`）。
- 非加密模式跳过目录加密（`CompressorFileSystem/ArchiveFormat/src/CatalogFinalizer.cpp:45-46`）。

### 3.4 可观察行为

密文长度恒为明文长度加 16 字节，前置 IV 每次加密重新生成（`EncryptionModules/Aes/src/mainCircle.cpp:24-36`）。

CTR 只提供机密性：解密接受任意长度不少于 16 字节的输入，剥离前置 IV 后按等长返回明文，错误密钥与任意比特翻转都得到等长乱码，按成功返回（`EncryptionModules/Aes/src/mainCircle.cpp:41-56`）。安全结论与实测条件见 `Y_MultipleAgentWorkflow/Engineering/工程实践.md` 第 14 节。

## 4. 私有性规则

Huffman 侧每个工人持有私有 `HuffmanCompression`，频次表、树根与码表随实例走，不得跨线程（`Y_Manager/CompressionLoop.cpp:221`）。

AES 侧每个工人持有私有 `AesEncryption`，CNG 密钥句柄与密钥流缓冲非线程安全，不得共享（`EncryptionModules/Aes/include/My_Aes.h:30`、`Y_Manager/DecompressionLoop.cpp:249`）；读线程另建私有实例（`Y_Manager/DecompressionLoop.cpp:117`）。

读线程与收尾阶段各自构造一份，目录块加密使用主线程那份实例（`Y_Manager/CompressionLoop.cpp:100-102`）。
