## 1. 适用范围

本篇给出 SFC 的全局结构模型：目录职责、依赖方向、压缩与解压的端到端链路、归档写入的唯一性规则，以及全库术语的唯一定义。
字节布局与字段宽度以 `Y_MultipleAgentWorkflow/ArchiveFormat/Router.md` 为权威，线程、队列与收口顺序以 `Y_MultipleAgentWorkflow/Pipeline/Router.md` 为权威。
本篇不复写接口签名，签名以头文件为准。

## 3. 依赖方向

- `Commons` 提供归档磁盘类型与常量、UTF-8 路径转换、超长路径 I/O 与二进制读写，`ArchiveFormat`、`DataIO`、`Strategy` 都依赖它。`CompressorFileSystem/Commons/include/ToolClasses.h:5` 例外地引入 `CompressorFileSystem/ArchiveFormat/include/EntryDetails.h`，反向引入见 `CompressorFileSystem/ArchiveFormat/include/BinaryStandardWriter.h:4-5`；其余同层子域头文件不由 `Commons` 引入。
- `ArchiveFormat` 依赖 `Strategy`：建档时用 `StrategyFactory::modeToId` 落盘策略号，收尾时用 `hasEncryption` 与 `IEncryption::encrypt` 加密目录块（`CompressorFileSystem/ArchiveFormat/src/HeaderWriter.cpp:18`、`CompressorFileSystem/ArchiveFormat/src/CatalogFinalizer.cpp:45`）；`DataIO` 只依赖 `Commons`，`Strategy` 只向两个算法模块取实现，三者之间单向无环。
- GUI 与内核的接触面是三个入口 `HeaderWriter::headerWriter`、`CompressionLoop::compressionLoop`、`DecompressionLoop::decompressionLoop`，读侧探测用的 `StrategyFactory::idToMode` 与 `hasEncryption`，以及对磁盘头的直读：`SFC_GUI/src/CompressionWorker.cpp:339-358` 按 `Y_flib::Constants::HEADER_SIZE` 读入字节、`memcpy` 进 `Y_flib::Header` 并取 `strategy` 字段。调用点集中在 `SFC_GUI/src/CompressionWorker.cpp` 与 `SFC_GUI/src/MainWindow_Compression.cpp`。

## 4. 压缩链路

1. `CompressionWorker::doCompression` 校验参数，剥掉用户输入里的 `.sy` 后缀，拼出输出路径与逻辑根名（`SFC_GUI/src/CompressionWorker.cpp:159-193`）。
2. `HeaderWriter::headerWriter` 建档：`EntryProcessor` 按 BFS 扫描文件系统，`BinaryStandardWriter` 序列化目录区，回填文件头内的自身长度与目录偏移。
3. `CompressionLoop::compressionLoop` 启动写、工人、读三种固定角色，工人数取逻辑核数，`SFC_WORKERS` 可覆盖。
4. `CompressionLoop::readerLoop` 用 `BinaryStandardLoader` 回读刚建好的目录区，产出 `FileTask` 队列与各文件「处理后大小」槽偏移；目录块此时 IV 槽全零，按明文解析。
5. `CompressionLoop::readerLoop` 用 `DataLoader` 逐 8 MB 读入并复制进池块，分配全局递增序号后投 `SafeQueue<BlockTask>`。
6. 工人各自 `StrategyFactory::createModules` 取私有模块，`ICompression::compress` 产出元数据块与数据块，`IEncryption::encrypt` 两次加密，数据块原地覆写。
7. `WriteSorter` 按序号重排，`DataExporter` 纯追加写盘，元数据块在前、数据块在后；文件完成时写线程记 `SizeFillEntry`。
8. `CatalogFinalizer::finalize` 先回填各文件处理后大小，再原地加密目录块。

## 5. 解压链路

1. `CompressionWorker::doDecompression` 读文件头，比对两处魔数，用 `StrategyFactory::idToMode` 还原本模式；加密包缺口令时直接返回错误。
2. `DecompressionLoop::decompressionLoop` 以模式与口令启动三段流水线。
3. 读线程用 `BinaryStandardLoader` 逐块读入，按 IV 槽状态解密后解析目录区，`EntryParser` 产出文件、目录与链接三个任务队列。
4. `DecompressionLoop::readerLoop` 先建目录，再从 `header.directoryOffset` 起顺序读数据区，每文件先发 `FileStart` 再逐块发任务，块输出上限由 `originalSize` 与已产字节预计算。
5. 工人各自 `createModules`，`IEncryption::decrypt` 两次解密，`ICompression::decompress` 产出明文并原地覆写池块。
6. 写线程经 `WriteSorter` 定序，见到 `FileStart` 即结算上一文件、开新 `DataExporter`，`exportDecompressedData` 纯追加写盘。
7. 流水线排空后 `DecompressionLoop::processLinks` 串行重建符号链接与 Junction。

## 6. 归档写入的唯一性规则

同一时刻只有一名写入者，写入按时序分三个阶段，阶段之间不并发；预留槽由阶段① 占位、阶段③ 回填，目录块区同在阶段③ 原地加密重写。
- 阶段① `HeaderWriter` 用 `ofstream` 建档，写文件头与目录区，并为所有预留字段占位（`CompressorFileSystem/ArchiveFormat/src/HeaderWriter.cpp:56`）。
- 阶段② `DataExporter` 用 `fstream` 只向文件末尾追加，写指针不回改（`CompressorFileSystem/DataIO/src/DataExporter.cpp:10`）。
- 阶段③ `CatalogFinalizer` 用 `fstream` 回填「处理后大小」槽，随后原地加密目录块；`finalize` 固定先回填后加密，非加密模式跳过加密（`CompressorFileSystem/ArchiveFormat/src/CatalogFinalizer.cpp:25`）。

## 7. 术语表

| 术语原名 | 中文名 | 一句话定义 | 定义位置 |
|---|---|---|---|
| `Header` | 文件头 | 定长文件头，记录策略号、格式版本与目录区偏移，长度与偏移由写入端回填 | `CompressorFileSystem/Commons/include/FileLibrary.h:63` |
| `FlagType` | 条目类型标记 | 1 字节磁盘标记，区分目录、文件、分割标准、逻辑根与三类 Windows 链接 | `CompressorFileSystem/Commons/include/FileLibrary.h:52` |
| standard | 标准 | flag 加变长名或路径再定长尾部组成的磁盘条目单元，目录区的目录块由标准串成 | `CompressorFileSystem/Commons/include/FileLibrary.h:109-135` |
| Separated | 分割标准 | 块的起始前缀，携带块长度；目录区的分割标准另带 16 字节 IV 槽，数据区的 IV 作为密文前缀随块写出 | `CompressorFileSystem/Commons/include/FileLibrary.h:156` |
| directory block | 目录块 | 目录区按 16 KB 阈值切出的标准聚合，解压时整块读出后解析，收尾阶段就地加密 | `CompressorFileSystem/Commons/include/FileLibrary.h:100` |
| data block | 数据块 | 数据区 8 MB 单元，压缩与加密的最小粒度，也是缓冲池的块单位 | `CompressorFileSystem/Commons/include/FileLibrary.h:99` |
| IV slot | IV 槽 | 目录块之前的 16 字节随机数位置，全零表示该块为明文；数据块的 IV 即密文首 16 字节 | `CompressorFileSystem/ArchiveFormat/src/BinaryStandardLoader.cpp:69` |
| `LogicalRoot` | 逻辑根 | 多文件任务的虚拟根目录，解压时以去掉后缀的包名为根还原 | `SFC_GUI/src/CompressionWorker.cpp:193` |
| `originalSize` | 原始大小 | 文件压缩前的字节数，解压时决定输出总量与每块输出上限 | `CompressorFileSystem/Commons/include/FileLibrary.h:166` |
| `processedSize` | 处理后大小 | 该文件全部块体的字节总和，加密块体含 16 字节 IV，不含每块 1 字节 `flag` 与 8 字节 `length`，收尾阶段回填 | `CompressorFileSystem/Commons/include/FileLibrary.h:167` |
| slot | 预留槽 | 建档时先占位、收尾时按绝对偏移回填的定长字段，回填记录由 `SizeFillEntry` 携带槽偏移与值 | `CompressorFileSystem/Commons/include/FileLibrary.h:164-168` |
| `CompressionMode` | 压缩模式 | 运行期四值枚举，决定压缩器与加密器组合，落盘为 `strategy` 字节，界面下拉首项为 `HuffmanOnly`，`setCompressionParams` 默认实参为 `HuffmanAES` | `CompressorFileSystem/Commons/include/RuntimeLibrary.h:27` |
| `StrategyModules` | 策略模块组 | 一次装配得到的压缩器与加密器二分体，每个工人各持一份私有实例 | `CompressorFileSystem/Strategy/include/StrategyFactory.h:14` |
| `DataBlock` | 缓冲块 | `std::vector<unsigned char>`，压缩与加密接口及缓冲池的通用载体 | `CompressorFileSystem/Commons/include/RuntimeLibrary.h:18` |
| backpressure | 背压 | 缓冲池在途块上限为 2 × (工人数 + 2)，读线程借不到块即阻塞在 `acquire` | `Y_Manager/CompressionLoop.cpp:45` |

## 8. 辨析表

| 易混对 | 关键差别 | 判定依据 |
|---|---|---|
| 目录块 与 数据块 | 目录块在解压开始时整块解析，数据块随文件顺序逐块流经工人；定义见第 7 节 | 偏移小于 `header.directoryOffset` 属目录区，自该偏移起属数据区 |
| 原始大小 与 处理后大小 | `originalSize` 是压缩前字节数，决定解压输出总量；`processedSize` 是全部块体的字节总和，定义见第 7 节 | 两者之差是该文件在归档中的体积变化，正值为膨胀 |
| 压缩 与 加密 | 压缩改变长度，由 `ICompression` 承担；加密由 `IEncryption` 承担，AES-128-CTR 下密文与明文等长，16 字节 IV 前置在密文之前，每块固定多 16 字节 | 压缩器为 `NullCompression` 即无压缩，加密器为 `NullEncryption` 即无加密 |
