## 1. 已落地的现状

**流水线主体（Y_Manager/CompressionLoop.cpp，总指挥编排三个角色）**

```
专职读线程 ──任务队列──> N 个计算工人 ──结果队列──> 专职写线程
      │                                                    │
      └──────────── BufferPool（在途块上限，唯一背压点）────────┘
```

- **读线程**：目录装载（BinaryStandardLoader 迭代 fileQueue）+ 逐块借池块复制数据 + 分配全局递增序号 + 提交任务；进度回调与 GUI 取消检查只在此线程；文件完成发结算消息；结束移交 takeBlockSpans()。
- **工人 ×N**（N = hardware_concurrency，fallback 4）：开头各自 `createModules(mode, password)` 一份私有模块；压缩 + 两次加密；**全程不碰缓冲池**（见 §3 死锁教训）。
- **写线程**：WriteSorter 按序号重排 → DataExporter 纯追加写盘 → 攒 SizeFillEntry 表；首个任务异常按序重抛并停刷。
- **收尾**：join 全部线程后 `CatalogFinalizer::finalize`（先回填大小槽后目录加密，类内焊死），GUI 侧唯一改动是 `compressionLoop(paths, mode, password)` 传参。

**组件（ThreadPool/，均带单测）**

- `SafeQueue.h`：管程队列模板。等待谓词析取（非空或已关）、退出判据合取（空且已关）、setDone 唤醒全部、结束后 push 拒绝。
- `WriteSorter.h`：区段连续性定序器（min/max 判据），`canWrite(seq, T&&)` 移动进表（修掉 lab 版整块拷贝），`takeInOrder()` 自理刷出编排（枚举期望区间 + 推进已写前缀），`drainAll()` 停刷出口。

**消息协议（Y_Manager/PipelineMessages.h）**

```
BlockTask       { sequence, inputData(池块,明文) }
PipelineMessage { sequence, kind: Block|Settlement,
                  encryptedMetadata(小,不进池), encryptedData(池块,密文), exception,
                  processedSizeOffset }
```

一个结构 + kind 标签，不用 variant。序号规则：块与文件结算都占号、异常消息不跳号——**无洞由结构保证**（读端单线程按序分配、工人每任务必产出、排空契约不丢），最坏情形全部在写端汇合一次刷出。空文件只有结算消息（不写任何字节），天然有序。

**其他修复**

- AES（My_Aes.h / mainCircle.cpp）：CSP 句柄缓存进实例（原每次 encrypt 都 CryptAcquireContext/Release，重 RPC 且多线程争抢）；加密核心零改动，黄金向量 186/186 通过。
- 运行期类型拆分（RuntimeLibrary.h，Y_flib::Runtime 子命名空间），FileLibrary.h 只剩磁盘格式。

## 3. 死锁教训（存档，别再犯）

工人循环一度写成"压缩完先还输入块、再从池借输出块"——看似更保守（任一时刻至多持 1 块），实际破坏了记账：**被还的块会被读线程抢走变成新任务占块**（任务队列无界），池被"排队任务 + 不可按序刷出的乱序结果"占满时，工人等块、写线程等队头序号、读线程等池——四方互等，永久 wedge（pack/huffman 任务快没踩中，AES 把窗口撑大必然踩中）。

正确结构（ThreadLab 原样）：**池块随消息走全链路，读线程是唯一借出方，写线程是唯一归还方，工人零池调用**——压缩产出先落在工人私有缓冲，再以加密输出**原地覆写**池块（明文→密文），块的所有权随消息移交写线程。依赖图无环，结构性无死锁；异常时块照常随消息到写线程，由唯一归还方统一还池，记账不被破坏。

## 4. 关闭协议（已实现）

总指挥集中关：join 读（取对账表和 takeBlockSpans）→ 关任务队列 → join 工人 → 关结果队列 → join 写（取 sizeFillEntries）→ CatalogFinalizer → 关池。错误/取消路径同序收口后统一重抛首异常；未收尾的归档本就解不开，中断语义与串行版一致。
