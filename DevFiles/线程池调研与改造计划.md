# 线程池改造计划

> v2 线程池由作者自行实现，本文是实施依据。
> 起点：`ThreadPool/` 目录为空；旧 v1 源码在提交 `4fe0335`。
> 现成组件：`BufferPool/`（§3）；单元测试在 `BuildTest/tests/`。
> 行号以 2026-09-03 工作区为准；v1 文件标注 `[4fe0335]`。

---

## 1. 要做什么

1. 重写线程池 v2：共享任务队列 + N 个 worker + WorkerEnv（线程私有模块对象）。
2. 主循环改为三段流水线：专职读线程 → 计算池 → 专职写线程。
3. BufferPool 接入主流程，作为背压与内存上限。

## 2. 为什么

v1 的四个缺陷决定了必须重写而不是修补：

| 缺陷 | 证据 | 后果 |
|---|---|---|
| 析构永久阻塞 | `_Thread.cpp:10-16` worker 无停止标志地永久 wait；`:25` `~Thread()` 调 join | 触发 delThread/析构即挂死，此前只是从未走到该路径 |
| 专有队列模型 | `addTask(trdName, task)` 路由到指定线程 | 负载不均；调度责任转嫁给调用方 |
| 异常终止进程 | 任务抛异常在 worker 栈上无人 catch | `std::terminate` |
| 无完成同步 | 无 waitAll/future | "所有块完成才能写头"无法表达 |

另：`MonitorTaskQueue` 管程本身写法正确（谓词 wait、锁内 notify），不需要重写队列逻辑——要换的是池的模型与生命周期。

## 3. 怎么做

### 3.1 ThreadPool v2

```cpp
using Task = std::function<void(WorkerEnv&)>;

class ThreadPool {
public:
    explicit ThreadPool(size_t n = std::thread::hardware_concurrency() - 2);
    ~ThreadPool();                    // drain：执行完剩余任务再退出
    template <class F>                // F 可调用为 R(WorkerEnv&)
    auto submit(F&& f)
        -> std::future<std::invoke_result_t<F, WorkerEnv&>>;
    void resize(size_t n);            // 扩容加线程；缩容置 exiting + notify
    void waitIdle();                  // 队列空 && busy==0
private:
    void workerLoop(std::atomic<bool>& exiting);
    std::vector<std::unique_ptr<std::atomic<bool>>> exitingFlags;
    std::vector<std::thread> workers;
    Y_LightLockQueue<std::function<void(WorkerEnv&)>> tasks;
    std::mutex mtx;
    std::condition_variable idleCv;
    size_t busy = 0;
    bool stop = false;
};
```

worker 循环三要点：任务在锁外执行；异常由 packaged_task 存入 future（submit 用 `shared_ptr<packaged_task<R(WorkerEnv&)>>` 包装，队列 lambda 为 `[pt](WorkerEnv& env){ (*pt)(env); }`）；busy 归零且队列空时 notify idleCv。

任务队列直接采用《开发流程与设计细节.md》681-726 行的 Y_LightLockQueue 定稿（654-668 行 bool readable 版本废弃）。

### 3.2 WorkerEnv（线程私有模块对象）

```cpp
class WorkerEnv {
public:
    template <class T, class... Args>
    T& module(Args&&... args) {      // 首次使用创建，线程生命周期内复用
        auto key = std::type_index(typeid(T));
        auto it = slots.find(key);
        if (it == slots.end())
            it = slots.emplace(key, std::make_unique<T>(std::forward<Args>(args)...)).first;
        return *static_cast<T*>(it->second.get());
    }
private:
    std::unordered_map<std::type_index, std::unique_ptr<void, void(*)(void*)>> slots;
};
```

依据：Aes 构造（SHA256 + 轮密钥扩展）与 Huffman 构造都是微秒级，线程内复用比每任务新建省，且无共享。§4 调研表明全部模块的不安全点都是可变成员状态，每线程一个实例即可全部消除，核心算法无需修改。工具对象不池化（管理成本高于新建），池化的对象是 8MB 块（§3.4）。

### 3.3 主循环接入（压缩侧先行，解压对称）

```
专职读线程 ──Y_LightLockQueue──> 计算池(N worker) ──Y_LightLockQueue──> 专职写线程
      │                                                                    │
      └────────────── 全局 BufferPool（容量 = 处理中块上限）────────────────┘
```

规则及依据：

1. **有状态的阶段用专职线程，无状态的阶段进共享池。** 读线程持有文件流/偏移/EOF 与目录迭代器；写线程持有 nextSeq/就绪缓冲/DataExporter；worker 无状态。
2. **读取不做池任务**：读任务需要背压（借不到块要阻塞），运行在计算池内会造成池内任务相互等待（thread pool starvation）。
3. **按序写出**：写线程用 `nextSeq + std::map<uint32_t, DataBlock> ready`，块 i 就绪且前序已写即写；结束条件 = 上游 Close() 且 ready 空。不需要 isLastOne 标记。
4. **错误传播**：任务 catch 后把 `std::current_exception()` 存入块（`std::exception_ptr`），写线程统一重抛。AES/Huffman 都会抛异常，不处理即 terminate。
5. **文件系统三处回写归写线程**（正确性只依赖写入串行有序）：
   - 每块长度回写：`exportCompressedData` 内部自带，无需改动；
   - 每文件 size 预留字段回写：`thisFileIsDone(offsetToFill)`，偏移来自目录迭代器 fileQueue，随"文件完成"消息传给写线程；
   - 收尾目录区加密：`encryptHeaderBlock`（`CompressionLoop.cpp:110`），放在写线程取完任务后的串行阶段。
6. **DataLoader 注意**：`getBlock()` 返回内部缓冲引用，`dataLoader()` 每次覆写该缓冲（`DataLoader.h:26/38`）。读线程提交任务前必须把数据复制/移动到池块，否则覆盖尚未完成的任务的数据。
7. 分两阶段：先单文件流水线，文件级并行放二期。

### 3.4 BufferPool 接入

- 容量 = 处理中块上限，建议 `2 × (worker数 + 2)`，内存峰值 ≈ 容量 × 8MB；
- 读线程借块填充，计算输出同样借块，写线程写完归还；借不到即阻塞，被最慢环节约束；
- metadata（16KB 级）不入池。

### 3.5 验收

1. 线程池四项测试（加入 `BuildTest/tests/`）：计数守恒（万级任务）、异常经 future 重抛、提交后立即析构不挂死且任务完成（v1 缺陷回归）、WorkerEnv 跨任务只构造一次 + resize 不丢任务；
2. GUI 四种策略压缩→解压与源一致；
3. WSL 中 TSan 检查。

## 4. 并发安全性调研

**结论：全部模块的不安全点都属于可变成员状态，不存在需要重写算法的模块；每线程一个实例（WorkerEnv）即可消除，核心算法不需要修改。**（CFB 块内串行不影响——并行单位是 8MB 块，块间 IV 相互独立。）

| 模块 | 事实（行号） | 并发处理 |
|---|---|---|
| `Aes` | `My_Aes.h:120 iv`、`:122 buffer` 每次 doAes 覆写（`mainCircle.cpp:27/42/53/56`）；`w[44]` 与各查表构造后只读 | 每线程一个实例；只读部分共享安全 |
| `Huffman` | `Heffman.h` freqTab/hashTab/treeRoot 被 compress/decompress 全程读写 | 每线程一个实例；每块独立树保证正确 |
| `DataLoader` | 内部缓冲被每次读取覆写，`getBlock()` 返回其引用 | 读线程持有；提交任务前移出数据（§3.3 第 6 条） |
| `DataExporter` | 读写双模式 fstream + 三处回写（§3.3 第 5 条），位置计算依赖写入顺序 | 写线程独占 |
| `BinaryStandardLoader` | fileQueue、块缓冲、游标状态 | 读线程或主控持有；回写偏移传给写线程 |
| `HeaderWriter` | 仅建档阶段一次性使用 | 启动阶段串行，无并发问题 |
| `StandardsWriter`/`Locator`/`EncodingUtils` | 无状态静态/纯函数 | 安全 |
| GUI | 压缩已在独立 QThread（`MainWindow_Compression.cpp:473-482`），信号跨线程安全 | 接入时确认 `m_stopRequested` 为 atomic |
