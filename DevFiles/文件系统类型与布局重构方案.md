## 1. 现状盘点

### 1.1 类型动物园及职责错位（`FileLibrary.h:14-35`）

| 类型 | 名义含义 | 实际承担的职责 | 问题评级 |
|---|---|---|---|
| `FileNameSize` (u32) | 文件名长度 | 文件名长度 + **回填槽位偏移**（`CompressionLoop.cpp:85` 的 `offsetToFill`） | ★★★ 名实不符最严重 |
| `DirectoryOffsetSize` (u64) | 目录偏移 | `directoryOffset` 头字段 + 目录扫描双游标（`tempOffset`/`offset`）+ **数据块长度字段**（`thisBlockIsDone` 回填的就是它）+ `blockPosition` 记录 | ★★★ 一名四职 |
| `FileSize` (u64) | 文件大小 | 源文件大小 + `DataExporter::processedFileSize` 回填值 | ★★ 双职但都是字节数，尚可 |
| `IvSize` = `array<uint8_t,16>` | —（名字带 Size 却是**值类型**） | IV 值；且 `sizeof(IvSize)` 参与槽位算术 | ★★ 误导 |
| `SizeOfMagicNum`/`SizeOfFlag` | 字段宽度 | 字段值类型 | ★ 命名歧义但波及面大，**本轮不动** |
| `UpSizeOfBuffer`/`ConstSize`/`MetadataMarker` | 缓冲上限/常量宽/标记 | — | ★ 低危，顺手可动可不动 |

### 1.2 布局算术散点（该收敛成单一权威定义的六处）

| 位置 | 算术 | 含义 |
|---|---|---|
| `HeaderWriter.cpp:26` | `HEADER_SIZE - sizeof(MAGIC) - sizeof(DirectoryOffsetSize) - sizeof(HeaderOffsetSize)` | 文件头内 `headerOffset` 槽位 |
| `HeaderWriter.cpp:46` | `HEADER_SIZE - sizeof(MAGIC) - sizeof(DirectoryOffsetSize)` | 文件头内 `directoryOffset` 槽位 |
| `HeaderWriter.cpp:47` | `directoryOffset + DirectoryOffsetSize(sizeof(MAGIC))` | 末魔数未写时的补偿（最绕的一处） |
| `DataExporter.cpp:8` | `currentPos - (dataSize + sizeof(DirectoryOffsetSize))` | 块长槽位（tellp 回算） |
| `BinaryStandardLoader.cpp`（encryptHeaderBlock） | `startPos - sizeof(IvSize)` | 目录块的 IV 间隙定位 |
| `FileLibrary.h:81-85` 大段注释 | — | 解释为什么不信任流位置、为何软件层手工维护 tempOffset——注释本身说明了一切 |

已有的收敛基础：`Constants::SEPARATED_STANDARD_SIZE` 等布局常量已经集中在 `FileLibrary.h`——问题只在**槽位定位算术没有跟着收敛**，仍在四处现算。

### 1.3 槽位记账链（现状）

`EntryProcessor`/`BinaryStandardWriter` 写目录时用 `tempOffset`/`offset` 双游标手工记账 → 收尾由 `BinaryStandardLoader` 重读目录建 `fileQueue`，队列元素 `pair<EntryDetails, FileNameSize>` 的 second 即每文件回填槽偏移 → `CompressionLoop` 在文件完成时取出交给 `thisFileIsDone`。

## 2. 重构项（按执行顺序）

### R1 槽位派生常量（纯加法，最先做、零风险）

在 `Constants` 内新增由布局推导的槽位定义，然后各算术点改引用：

```cpp
// 文件头内两字段的槽位（相对文件头起点；布局见 Header 结构体）
constexpr ConstSize HEADER_OFFSET_SLOT =
    HEADER_SIZE - sizeof(SizeOfMagicNum) - sizeof(DirectoryOffsetSize) - sizeof(HeaderOffsetSize);
constexpr ConstSize DIRECTORY_OFFSET_SLOT =
    HEADER_SIZE - sizeof(SizeOfMagicNum) - sizeof(DirectoryOffsetSize);
// 数据块前缀中"块长字段"的宽度
constexpr ConstSize BLOCK_LENGTH_FIELD = sizeof(DirectoryOffsetSize);
constexpr ConstSize IV_BYTES = 16;   // 供算术用；IvSize 是值类型，别再 sizeof(值类型)
```

替换点：`HeaderWriter.cpp:26/46`、`DataExporter.cpp:8`、encryptHeaderBlock 的 `sizeof(IvSize)`。每处都是同一表达式换个名字，行为零变更。

### R2 类型改名（机械替换 + git grep 清零验收）

原则：**偏移与长度分开命名**。新增别名而非改造底层：

```cpp
using SlotOffset = uint64_t;   // 回填槽位在归档内的绝对偏移
using BlockLength = uint64_t;  // 数据块长度字段
```

- `FileNameSize` 的槽位用法 → `SlotOffset`：`CompressionLoop.cpp:85`、`fileQueue` 的 pair 第二型、生产/消费两侧（EntryParser / BinaryStandardLoader / DecompressionLoop 对应处）；
- `DirectoryOffsetSize` 的块长用法 → `BlockLength`：`thisBlockIsDone`/`thisFileIsDone` 签名、`exportCompressedData` 局部变量、`SEPARATED_STANDARD_SIZE` 的组成说明；
- `FileNameSize`/`DirectoryOffsetSize` 保留其余正当用途（文件名长度、目录偏移/游标）不动。

每改一组：`git grep 旧名` 确认目标用法清零 → 构建 → 原子提交。

### R3 布局结构体 + static_assert（纯加法，只定义不写入）

```cpp
#pragma pack(push, 1)
struct SeparatedPrefix { FlagType flag; IvSize iv; BlockLength length; };
struct FileStandardTail { FileSize originalSize; FileSize processedSizeSlot; };
#pragma pack(pop)
static_assert(sizeof(SeparatedPrefix) == SEPARATED_STANDARD_SIZE);
static_assert(sizeof(FileStandardTail) == sizeof(FileSize) * 2);
```

**边界（重要）**：结构体本轮只作布局的权威定义与编译期校验器，**写入路径仍走逐字段 `writeBinaryStandards` 按序写**——不改成整体 `write(&struct)`，避免触碰写序与填充。等将来 v2 动格式时再议整体写。

### R4 fileQueue 语义显式化

`std::queue<std::pair<EntryDetails, Y_flib::FileNameSize>>` → 定义具名结构：

```cpp
struct FileTask {
    EntryDetails entry;       // 待处理文件的目录条目
    SlotOffset  sizeSlot;     // 该文件"处理后大小"回填槽在归档中的偏移
};
using FileTaskQueue = std::queue<FileTask>;
```

波及：`ToolClasses.h` 的 `EntryQueue` 定义、CompressionLoop / DecompressionLoop 消用处、EntryParser / BinaryStandardLoader 生产处。纯类型替换，行为零变更。

### R5 输出文件三阶段所有权注释

在 `HeaderWriter.h` / `DataExporter.h` / `BinaryStandardLoader.h` 三处类头注释钉死同一段话：

> 归档输出文件的写入分三阶段单线程接力，任何阶段不得并发写：
> ① HeaderWriter（ofstream，建档期：头+目录+槽位预留）
> ② DataExporter（fstream，数据期：逐块追加+每块/每文件回填）
> ③ BinaryStandardLoader::encryptHeaderBlock（fstreamForRefill，收尾：目录区原地加密）
> 并行化时 ②③ 归专职写线程，见《线程池调研与改造计划.md》§7.1。

## 4. 明确不做的事

- 不改任何 on-disk 字节：不对齐、不整体写结构体、不动字段顺序；
- 不动加密模块与 AES 侧类型；
- 不做 trailer/目录后置的格式重设计（那是另一维度的未来选项，见《线程池调研与改造计划.md》的讨论）；
- 不顺手"简化"任何写序逻辑——本轮唯一目的是让**现有的正确性**变得可读、可查、可并发对接。
