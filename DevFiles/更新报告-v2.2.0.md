# 更新报告：v2.2.0 — Pipeline

> 2026-09-07。对照上一发布版本 v2.1.0（2026-04-16）；涵盖近两周 37 个提交与发版当日工作。技术细节见《开发流程与设计细节》《线程池调研与改造计划》（实施记录）、《性能报告-2026-09-07》。

## 一句话总览

压缩内核从单线程串行升级为三段流水线（专职读 → N 工人并行计算 → 专职写），大文件场景实测提速 6.9 倍；同时完成一轮文件系统类型重构、长路径/符号链接修复与 AES 安全加固，归档格式保持向后兼容。

## 性能（HuffmanAES，同机同输入实测，以吞吐量计）

| 场景 | 数据特征 | 旧版吞吐 | 新版吞吐 | 提升 |
|---|---|---|---|---|
| 正常文件 | 均 311KB/文件 | 19.1 MiB/s | **131.9 MiB/s** | **6.9×** |
| 长路径极端（pnpm 深巢，路径最深 267 字符） | 均 75KB/文件 | 14.7 MiB/s | **52.6 MiB/s** | **3.6×** |
| 小文件极端 | 均 172B/文件 | 962 文件/s | **1,743 文件/s** | **1.8×** |

每压缩 1 GiB 的耗时：正常文件从约 54 秒降到约 7.8 秒，长路径从约 70 秒降到约 19.5 秒。全量参考：13.47GiB / 45,390 文件的项目目录以 106.5 MiB/s 压缩完毕；三个全量归档解压后文件数与字节数与源精确一致。规律：文件越大吞吐提升越大——能摊到多核上的只有计算段，读写端点是所有场景共享的地板；小文件场景的进一步优化方向已存档（调度合批、端点流水化），本期未实施。

## 核心架构：多线程压缩流水线

- **三段固定角色**：专职读线程（目录装载、借池块、分配全局序号）→ N 个计算工人（N = CPU 逻辑核数，各持一份私有 AES/Huffman 模块）→ 专职写线程（按序号重组、纯追加写盘）。有状态的阶段专职化、无状态的计算进对称池，读写不进池。
- **背压与内存上限唯一落点**：全局 BufferPool，容量 2×(N+2) 个 8MB 块；读线程借不到块即阻塞，下游的慢自动拖住上游；内存峰值 ≈ 容量 × 块大小，一目了然。
- **防死锁不变量**：池块随消息走全链路，读线程唯一借出、写线程唯一归还、工人零池调用（加密输出原地覆写输入块）。开发中曾因工人借还次序错误造成四方互等死锁，按此结构重写后消除，教训已存档。
- **关闭协议**：总指挥集中收口（join 读 → 关任务队列 → join 工人 → 关结果队列 → join 写 → 收尾器 → 关池），错误与用户取消统一重抛首异常。
- 新组件：`ThreadPool/SafeQueue.h`（管程阻塞队列）、`ThreadPool/WriteSorter.h`（乱序结果区段定序），各带单元测试（test_safequeue / test_writesorter 入测试工程）。
- 归档字节布局与旧版完全一致：非加密模式经 `tool_archivebaseline` 与串行版产物逐字节对比验收。

## 写路径三阶段重构（零字节变更）

- 建档（HeaderWriter）→ 纯追加写数据（DataExporter）→ 收尾（新增 CatalogFinalizer：统一回填各文件"处理后大小"槽并原地加密目录区，次序焊死类内）。
- 块长度直写真实值，删除每块两次 seek 回补；DataExporter 从此不 seek 回改，BinaryStandardLoader 回归纯读类。

## 可靠性与兼容性修复（v2.1.0 以来）

- **长路径**：`\\?\` 前缀 + Win32 API 查询/枚举/创建/读取，超长路径（260+）全程可用；修复首个 16KB 目录块只有目录条目时压缩流程静默跳过文件数据的缺陷。
- **符号链接/Junction**：只存链接自身记录的原始目标（不解析），解压在普通文件与目录恢复后统一重建；归档格式升 v2（新增三种链接标志），读取端继续兼容 v1。
- **AES 修复与加固**：providers 数组越界、死成员、无效 resize 三处缺陷；取缔裸指针；主密钥与轮密钥析构时 SecureZeroMemory 擦除。
- **AES 性能**：CSP 句柄缓存进实例（原每次加密都获取/释放系统加密句柄）。
- 修复解压中文输出目录乱码（v2.1.0 已含，此处一并归档）。

## 工程与代码质量

- 文件系统类型与布局重构 R1-R7（零行为变更，逐字节验收）：布局常量收口 `Header::Layout`、SlotOffset/BlockLength 分型、布局结构体 + static_assert、FileTask 具名结构、读写两侧偏移游标收口嵌套类、三阶段写入时序注释。
- 运行期类型拆分 `RuntimeLibrary.h`（`Y_flib::Runtime`），`FileLibrary.h` 仅存磁盘格式类型。
- 构建与测试合并至根目录 `BuildTest/`；GUI 目录更名 `SFC_GUI`；CompressorFileSystem 拆分四模块；删除旧线程池/Schedule/DataBlocks 死代码。
- 新增 CLI 验收工具 `tool_archivebaseline`（可复现样本 + roundtrip/verify），测试工程扩至 6 个单测目标。
- 删除压缩/解压链路残留 DEBUG 输出。

## 已知限制与后续方向

- 解压路径仍单线程（约 20 MiB/s），属下一优先级优化。
- 小文件场景读写端点未优化（调度合批等待实测决策）；ThreadSanitizer 检查未执行。
- IV 生成的跨平台抽象未提取（当前仅 Windows 分支）。
